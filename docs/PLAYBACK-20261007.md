## Current architecture and working reference

Runtime manifests/registry/process supervision live in `source/hr54-re/reboxd/`.
The module SDK serves bounded concurrent requests over private Unix sockets and
sets explicit package/data/socket environment paths. Each integration lives in
`source/hr54-re/modules/<id>/`; its `/play` handler resolves an opaque item and
returns an inert plan. `reboxd/playback.c` owns session arbitration, transport,
proxying, and the fixed `/var/opt/hr54/bin/hr54-play-url` subprocess. That shell
helper sends vendor `playURL` IPC through `uconntest`; no browser video API is
involved.

Jellyfin calls PlaybackInfo, selects the server's TS transcode URL, and streams
through its own relay and core's loopback module proxy. Core verifies HTTP 200
and a TS sync byte before exposing `video/mp2t` to the vendor decoder. Native
and Android clients share this generic plan contract. The old daemon includes
module-owned implementations only for its transitional build; it is not the
current receiver runtime.

## YouTube

The module invokes its receiver Python 3.14 runtime with the package-owned
`resolver.pyc`, mode `play`, the selected eleven-character video ID, and page
`0`. This imports `yt_dlp` from the private `yt-dlp.zip`; it does not launch a
shell yt-dlp command. The existing resolver selects bounded H.264 HTTP video and
AAC-LC HTTP audio, with the `visionos` extractor client. Signed URLs stay private.
Separate tracks are intentionally fetched into bounded FIFO feeders and joined
by the existing MOV-to-MPEG-TS packet copier on the HR54. A single fresh
resolution is retained if the relay fails before any media bytes.

`jNQXAC9IVRw` (“Me at the zoo”, 19 seconds) played before edits. Both HTTPS
feeders exited successfully; the hardware configured AAC and presented frames.
The user confirmed visible video and audible audio. No URL-extraction, format,
worker-path or shared playback regression was reproduced in that test. The
successful selection/remux behavior is preserved. Diagnostics now expose worker
paths, resolver/relay exit status, selected format IDs and redacted URL origins.
Resolver failures log only TLS/format/authentication/extraction categories,
because yt-dlp error text can contain signed URLs or credentials. Worker exit
status is retained instead of unconditionally killing a completed worker first;
EOF with a failed relay is treated as a failure rather than successful drain.

## Frigate: confirmed defect and fix

Configuration comes from module-data `frigate/config.json`, falling back to the
existing module default `192.168.88.39:5000`. Discovery uses `/api/config` and
`/api/go2rtc/streams/<configured-stream>`; camera identifiers are mapped through
`live.streams` and the configured go2rtc stream names. The tested camera is
`camera_07c3`, mapping to `camera_07c3_live`.

The configured server reported `0.18.0-77a66e7`. The previous plan requested:

```
http://192.168.88.39:5000/stream.ts?src=camera_07c3_live
```

This returned HTTP 200 **text/html**, the Frigate application. The previously
used `/api/go2rtc/api/stream.ts` returned 404. Direct go2rtc HTTP port 1984 was
unavailable. A direct plan only waited for the player helper's successful IPC
submission, so its active status did not prove playable media.

The exposed `/live/mse/api/ws?src=camera_07c3_live` route successfully upgraded
with HTTP 101 and negotiated H.264/AAC fragmented MP4. The new module-owned
relay requests only go2rtc's H.264/AAC selectors, validates the WebSocket
handshake and bounded frame/control/fragment handling, and copies fMP4 packets
into MPEG-TS. It links the same minimal FFmpeg 8.0 MOV/TS/file/pipe libraries
already used by YouTube. No decoder or encoder is opened, no live media is
written to disk, and no new server-side transcode/configuration is introduced.
Unsupported tracks are omitted; H.264 is required and dimensions over 1920×1080
are rejected. Existing video-only cameras can omit audio.

Frigate now returns a `moduleProxy` plan and uses core's existing TS validation
and player invocation. Stop retires only the matching session and releases the
owned worker/group/upstream socket. Live failures retire the session and expose
an error in module status, with exit/signal/HTTP diagnostics in its private log.
The HR54 configured AAC, started the decoder and presented camera frames; the
user confirmed the live camera was visible. The observed stream is 640×720.

Primary protocol references used during diagnosis:
[Frigate nginx routes](https://github.com/blakeblackshear/frigate/blob/dev/docker/main/rootfs/usr/local/nginx/conf/nginx.conf),
[go2rtc MSE handler](https://github.com/AlexxIT/go2rtc/blob/master/internal/mp4/ws.go),
and [go2rtc codec selectors](https://github.com/AlexxIT/go2rtc/blob/master/pkg/mp4/mime.go).
The deployed server's responses, not repository defaults, determined the fix.
